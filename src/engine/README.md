# Simulation Engine Components

## Overview
The `src/engine/` directory contains the business logic and simulation components of the HFT system.

## Components

### 1. Replay Engine (`ReplayEngine.cpp/h`)
*   **Role**: The conductor of the simulation.
*   **Function**: Reads the CSV data file line by line, parses Market Events (Trades), and updates the Order Book.
*   **Flow**:
    1.  Parse CSV line.
    2.  Update `LatencyQueueSimulator` (check for order fills).
    3.  Update `OrderBook` with new market data.
    4.  Update `FeatureExtractor`.
    5.  Call `DecisionEngine::on_event` to generate new quotes.

### 2. Decision Engine (`DecisionEngine.cpp/h`)
*   **Role**: The "Brain" of the trading bot.
*   **Strategy**: Avellaneda-Stoikov Market Making.
*   **Logic**:
    *   Calculates **Reservation Price** ($r$) based on mid-price, inventory risk, and an alpha signal.
    *   **ML Mode**: Uses the compiled LightGBM model (`model_compiled.c`) to predict price movement ($\alpha$).
    *   **Baseline Mode**: Uses a random number generator to perturb the reservation price (20% probability) for benchmarking.
    *   Places Bid and Ask orders around $r$.

### 3. Execution Simulator (`ExecutionSimulator.cpp/h`)
*   **Role**: The "Exchange" simulator.
*   **Function**: Tracks the status of active orders and determines if they are filled based on market trades.
*   **PnL Tracking**: Calculates Realized and Unrealized PnL, and total Equity.

### 4. Latency Queue Simulator (`LatencyQueueSimulator.cpp/h`)
*   **Role**: Simulates network and processing delays.
*   **Function**:
    *   When the Decision Engine places an order, it enters a "Latency Queue".
    *   The order is only "active" in the Execution Simulator after a randomized delay (e.g., 100µs - 500µs).
    *   This prevents "look-ahead bias" where the bot reacts instantly to a trade that just happened.

### 5. Feature Extractor (`FeatureExtractor.cpp/h`)
*   **Role**: Data preprocessing for ML.
*   **Function**: Computes features like Order Book Imbalance, Spread, Arrival Rate, VPIN, and Microprice from the raw Order Book state.

### 6. Compiled Model (`model_compiled.c/h`)
*   **Role**: The machine learning model.
*   **Origin**: Generated by `python/tune_model.py` or `python/train_model.py` using **Treelite**.
*   **Format**: Pure C code representing the decision trees of the LightGBM model.
*   **Performance**: Allows for extremely fast inference (no Python interpreter overhead) within the C++ hot path.
